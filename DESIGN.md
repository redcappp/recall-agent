# Recall: evidence across time

The difficult question is not “what does this cost?” but “did the five products we discussed Monday change?” Recall preserves the original question, answer, timezone, timestamp, search queries, source URLs and retrieved text together. An old answer is a historical claim, never authority for current truth. The agent is instructed to recover the exact shortlist first, normalize billing units, verify current primary sources, and distinguish confirmed changes from unknowns. Retrieval time does not establish a change’s effective date.

## Execution

A Node/Express server calls Claude’s Messages API in a bounded tool loop. The model has exactly one tool: Tavily web search, returning page text as well as links. Independent queries run concurrently. There are at most eight searches and five model calls; the last call must synthesize. Search failures are explicit tool errors, so “could not verify” cannot silently become “unchanged.” The browser receives live progress via newline-delimited JSON. Server-configured keys never reach the client. Users can supply their own keys through password fields; these stay in page memory and are sent per request, never saved in the archive. Per-browser opaque HttpOnly cookies separate histories, and per-session locks prevent interleaved writes. Completed turns are persisted with atomic replacement.

## Memory choice and tradeoffs

For this small evaluation workload, inject all dated questions and answers with source excerpts capped at 1,500 characters per result; full snapshots stay on disk. This avoids embedding retrieval missing a seemingly unrelated “those five” reference, avoids lossy summaries, and makes every recalled statement auditable. A strict archive character budget fails explicitly instead of silently forgetting. This is deliberately a small-history architecture: repeated source text raises latency and cost, and character limits are only an approximate token bound. It needs a measured retrieval layer before long-term production use. The archive is supplied as untrusted evidence; webpage instructions are also explicitly distrusted. Prompt instructions mitigate injection but are not a security guarantee.

I rejected a multi-agent planner and mandatory search on every turn: they add latency without helping greetings or stable explanations. I rejected searching only recent news: current official pricing plus dated historical evidence are both necessary. I rejected invented demo memory: absent conversations must produce clarification. No claim is made that the model reliably follows every comparison instruction; this requires evaluation.

## Another week

Build a dated regression corpus covering timezone boundaries, missing/ambiguous Mondays, changed billing cadence, contradictory sources and search outages. Measure citation entailment, entity recall, change classification, p50/p95 latency and spend. Add SQLite indexed chronological/lexical retrieval with adjacent turns, a constrained query planner, and explicit evidence-backed comparison records; keep original turns as the source of truth. Add token streaming, citation-entailment validation, cancellation, retries with jitter and deadline propagation. The current UI sanitizes Markdown and renders source links; that does not establish citation correctness. Production needs authenticated accounts, stronger CSRF defenses beyond the current Origin check, quotas, encrypted storage, retention controls and multiprocess-safe persistence. Today this binds only to localhost and is a local evaluation app.
